# Binding project policy — planning only

This repository-specific policy overrides generic scaffolder templates, agent defaults, ceremonies and examples wherever they conflict.

1. **Scope:** discovery, research and phased design only. Preserve all original application sources, CMake behavior and existing explanatory docs. Do not mistake illustrative enterprise scenarios for implemented capabilities.
2. **Authority:** only user-approved bounded work. No automatic delegation, issue pickup, weekly enforcement, background Scribe launches, Ralph loops, watchers, schedules, workflows, commits or pushes. Report work in files and summaries, not remote issues.
3. **Local state:** `.squad/config.json` explicitly selects `local`. Use this repository's team root. Do not inherit or alter the personal team, create state branches, or enable remote/external memory providers.
4. **Tools:** use installed tools only. Do not install/upgrade dependencies or run `npx` downloads. The generated MCP entry was changed to installed `squad state-mcp`; it is configuration, not evidence of a running/reachable bridge. Local filesystem persistence needs no bridge.
5. **Privacy:** never read `.env` files, persist user emails/secrets, or send repository code to external services. A future graph must exclude secrets, model source documents as untrusted data, retain provenance, and define deletion/invalidation before ingestion.
6. **Evidence:** cite exact repository paths and meaningful line spans; record command/environment and distinguish observations, derivations, proposals and unverified claims. Never invent benchmarks, reviews or production requirements.
7. **Reviews:** retain Rai's critical safety gate and Fact Checker's contradicted-fact gate. If reviewer lockout applies, assign a different reviser, never the rejected original author. Do not claim either review occurred merely because the roles exist.
8. **Persistence:** approved identities and casting snapshots are durable. Histories and audit trails are append-only with `merge=union`; no fabricated personal experiences. Scribe may maintain local files when explicitly assigned, but never auto-commit.
9. **Validation:** isolated, uniquely named build artifacts stay beneath `.squad/.scratch/` and are removed after checks. No application changes to make validation pass. Missing tools/platforms are documented limits.
10. **Approval gate:** implementation, new dependencies, hosted services, remote publication and automation require separate user approval. No milestone has a fabricated calendar deadline.
